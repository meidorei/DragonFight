# 可复制的 AI 角色制作任务

本游戏不自动调用 AI。把以下内容交给你选用的图像工具或编程 AI；先使用少量帧验证一致性，再制作全套。角色图像采用自己的设定，避免把参考游戏素材当作模板直接搬运。

## 一、角色设定与参考图

```text
为原创横版格斗角色「<名字>」设计一张全身参考图。
定位：<近战 / 远程 / 重装>。
人设：<一句话性格与背景>。
必须保留的识别特征：<发型>、<服装轮廓>、<配饰>。
配色：<主色>、<副色>、<肤色 / 发色>。

风格：约 2.5～3 头身的 Q 版平涂，简洁有力的轮廓，适用于 2D 格斗游戏。
镜头：正交侧视，朝右，全身，放松战斗姿势。
纯透明背景，不能出现地面、投影、文字、水印或棋盘格。
人体与配饰完整，不裁切。不要背景场景，不画特效。
```

保存确认过的参考图，每次制作动作都附上同一张，不要依赖模型记住之前的对话。

## 二、单动作精灵条

```text
以附图作为唯一角色外观参考，为同一角色绘制「<动作名称>」动画。
保持发型、脸部特征、服装、配色、头身比例完全一致。
Q 版平涂，正交侧视，每一帧都朝右；镜头和人物大小不能变化。

输出一行 <N> 帧，单帧 256×256，总尺寸 <N×256>×256。
每帧全身，脚底参考锚点为单帧的 (128,232)。落地帧的脚线一致。
无帧间距，无边框，无格线，无文字编号，无地面和投影。
透明背景；武器、手脚和发梢不能出格，保留安全边距。
不画飞行弹道、冲击波或光效，它们由游戏单独呈现。

逐帧动作：
1. <具体姿势>
2. <具体姿势>
……
N. <具体姿势>
```

如果模型不能可靠生成横条，改为每次生成一张 256×256 单帧，用上一帧和角色参考图同时做参考，最后在实验室组合。不要为了凑尺寸拉伸角色；用画布留白和锚点调整。

建议动作描述：

- 待机 4 帧：中立戒备 → 肩膀轻微上提 → 呼吸高点 → 回到戒备。
- 行走 6 帧：右脚触地 → 重心前移 → 双脚经过 → 左脚触地 → 重心前移 → 回到经过姿态；短步幅，头部高度稳定。
- 轻击 4 帧：收拳 → 出拳 → 打击伸展 → 收势。
- 技能 6 帧：蓄势一 → 蓄势二 → 发力一 → 发力二 → 回收一 → 戒备。
- 大招 8 帧：前三帧蓄势，第四至第五帧爆发，后三帧收势；光效独立制作。

## 三、交给编程 AI 的接入任务

```text
你正在 C:\CWorkWork\DragonFight 中新增角色。
先阅读 docs/角色制作规范.md、docs/技能扩展.md、src/schema.js。

角色 ID：<小写英文id>
名字：<中文名>
定位：<近战 / 远程 / 重装>
外观素材位置：<实际路径>
技能概念：<分别描述三个技能和大招>

请执行：
1. 复制 templates/character 到 characters/<id>，保留完整动作结构。
2. 填写 character.json；素材相对路径、尺寸、帧数和锚点必须与实际文件一致。
3. 修改 name、role、description、color、portrait 和基础属性；使用独立 ID。
4. 优先用内置 melee/projectile/dash/area/shield/buff 配置效果。
5. 攻击动作设置 phases，使动画的前摇、生效、后摇与逻辑一致。
6. 如必须写特殊技能，新增独立模块并在 src/plugins/registry.js 显式注册，
   不改战斗引擎，不从 JSON 动态执行代码，不读文件或网络。
7. 在 characters/manifest.json 添加 <id>/character.json。
8. 运行 npm run check、npm test、npm run build，修复实际失败。
9. 给出训练场验证步骤和修改清单，不把未经检查的图片标成合格。

限制：不安装依赖，不调用外部 AI API，不覆盖其他角色，不修改系统环境。
素材缺失时明确保留占位图并列出缺失项，不伪造动作已经制作完成。
```

## 四、给 AI 的评审清单

```text
审核这个角色是否可交付：
- 所有必需动作均有可解码素材，尺寸和帧索引正确。
- 角色朝右、透明背景、脚线一致，换动作没有突然缩放和裁切。
- 前摇清晰，命中帧与生效时间一致，收招后回到正常待机。
- 角色进入 1V1、2V2、训练和挑战时没有错误。
- 防御、倒地、起身、大招消耗和技能冷却正常。
- 新技能不需要修改引擎，没有远程依赖或隐式模型调用。
区分自动校验结果与人工目视结果，列出仍需确认的内容。
```
