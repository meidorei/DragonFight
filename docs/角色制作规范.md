# DragonFight 角色制作规范 v1

目标：让 AI 生成的角色素材通过固定接口进入游戏。外观动画与战斗判定完全分开；换图不改变伤害、距离或节奏。

## 1. 复制模板

将 `templates/character/` **整个文件夹**复制为 `characters/moon-knight/`。不要覆盖已有角色。修改目录内 `character.json` 的 `id`、`name`、`role`、`description`、`color`，再在 `characters/manifest.json` 的 `characters` 数组末尾添加 `"moon-knight/character.json"`。ID 必须唯一，2～40 位，小写字母开头，只用小写字母、数字、连字符。

所有路径相对于 `character.json` 所在目录；使用英文文件名、正斜杠，不使用绝对路径、远程链接、上级目录。无需修改引擎、选人界面或任何模式代码。刷新网页后加载新清单。

## 2. 角色设定卡

先确定名字、战斗定位、性格、主副色、身高比例、发型、服装和三个必须保留的识别特征。画一张独立的全身参考图，后续每次生成动作都带上同一张图。首版建议所有角色沿用约 2.5～3 头身，使用干净的 Q 版平涂，不要求像素画。

美术标准：

| 项目 | 标准 |
| --- | --- |
| 格式 | 带 alpha 的透明 PNG；推荐 RGBA，禁止假透明棋盘格 |
| 单帧尺寸 | 默认 256×256；配置允许 32～1024 |
| 视角 | 正交侧面，默认朝屏幕右方；朝左由程序镜像 |
| 脚底锚点 | 默认 `(128,232)`，每个动作可配置 |
| 角色尺寸 | 站立时约占画面高度 180～210px，各动作保持比例 |
| 安全边距 | 建议至少 12px，拳脚、头发与武器不可被裁切 |
| 背景 | 透明，无地面、投影、网格、文字、编号、水印 |
| 外置内容 | 飞行道具、大型冲击波、光效单独处理，不画入身体帧 |

不要要求 AI 一次画完所有动作。优先逐动作生成横条，或生成独立帧后在实验室组装。AI 未必严格遵守尺寸、透明度和一致性，导入前必须检查。

## 3. 必需动作

| 配置键 | 动作 | 模板帧数 | 默认 fps | 循环 |
| --- | --- | ---: | ---: | --- |
| idle | 待机呼吸 | 4 | 6 | 是 |
| walk | 行走完整步态 | 6 | 12 | 是 |
| jump | 起跳、腾空、下降姿态 | 3 | 12 | 否 |
| guard | 防御 | 2 | 6 | 是 |
| dodge | 后撤闪避 | 3 | 12 | 否 |
| hurt | 受击 | 2 | 12 | 否 |
| knockdown | 倒地 | 3 | 12 | 否 |
| getup | 起身 | 3 | 12 | 否 |
| ko | 失败倒下 | 3 | 12 | 否 |
| victory | 胜利 | 4 | 12 | 否 |
| light | 轻击 | 4 | 12 | 否 |
| heavy | 重击 | 5 | 12 | 否 |
| air | 空中攻击 | 4 | 12 | 否 |
| skill1 / skill2 / skill3 | 三个技能 | 各 6 | 12 | 否 |
| ultimate | 大招 | 8 | 12 | 否 |

帧数不是引擎常量，每动作支持 1～64 帧。起步时可以复用样板，但正式素材要有可辨识的蓄力、发力与收招。落地姿态保持共享脚线；跳跃的高度主要由游戏物理系统控制，素材不要自行将角色大幅上移。倒地动作保持身体可见，不能把旋转后的人物裁到帧外。

## 4. 动画配置

横向精灵条：一行 N 帧，尺寸为 `(单帧宽 × N) × 单帧高`，没有帧间距或边框。

```json
{
  "src": "light.png",
  "frameWidth": 256,
  "frameHeight": 256,
  "frames": 4,
  "fps": 12,
  "loop": false,
  "anchor": [128, 232]
}
```

独立图片序列：用 `files` 替换 `src`，数组顺序就是播放顺序，每张必须为单帧尺寸。

```json
{
  "files": ["walk/01.png", "walk/02.png", "walk/03.png", "walk/04.png"],
  "frameWidth": 256,
  "frameHeight": 256,
  "frames": 4,
  "fps": 12,
  "loop": true,
  "anchor": [128, 232]
}
```

游戏内身体默认按 192px 高绘制，锚点随之缩放。`hurtbox` 是游戏世界单位，不从不透明像素自动生成；图片中武器变长不会自动增加攻击距离。

攻击动画按照招式总逻辑帧数播放，`fps` 主要用于非攻击状态和实验室预览。若指定 `phases`，攻击帧会分别映射到前摇、生效与后摇，避免发力画面与命中时机错位，格式见下节。未指定时均匀映射完整动画。

## 5. 基础属性与招式

`stats.health`：100～10000；`stats.speed`：60～700 游戏单位／秒；`stats.jump`：200～1000 初始向上速度。`hurtbox.width`：20～180，`height`：40～250。推荐沿用模板平衡，先换素材，再微调属性。

每个角色必须提供 `light`、`heavy`、`air`、`skill1`、`skill2`、`skill3`、`ultimate` 七种招式。

```json
{
  "name": "月牙斩",
  "animation": "skill1",
  "startup": 12,
  "active": 6,
  "recovery": 22,
  "damage": 85,
  "knockback": 280,
  "stun": 18,
  "cost": 15,
  "cooldown": 70,
  "knockdown": false,
  "phases": {"startup": [0,1], "active": [2,3], "recovery": [4,5]},
  "effects": [{"type":"melee","at":0,"range":120,"height":125}]
}
```

时间统一使用 60Hz 的逻辑帧，60 帧为一秒。`at` 从生效阶段第 0 帧起算。近战／范围效果生效后持续到该招式生效阶段结束；每个效果对每名敌人最多命中一次。多段攻击需写多个效果、分别指定 `at`，伤害会按每个效果分别计算。弹道在 `at` 时发射，离开角色后继续飞行。

`phases` 的三个数组分别是该阶段播放的动画索引（从 0 开始）；索引必须小于动画的 `frames`。详见 [技能扩展](技能扩展.md)。

大招消耗固定为 100。不要通过极端范围、零后摇或大量重复效果制造不可交互的角色；建议在训练场和三种 CPU 难度下都试打。

## 6. 实验室与验收

1. 打开角色实验室，选样板动作，核对单帧宽高、脚线和 fps。
2. 加载自己的精灵条或 PNG 序列。序列按文件名自然排序，使用 `01.png` 等命名。
3. 检查透明背景，逐帧查看是否裁切、服装变形、角色比例漂移，翻转后确认武器位置可接受。
4. 导出精灵条和 JSON 片段，将文件手动保存到角色目录；将片段合并到 `animations` 对应动作。
5. 运行 `npm run check`。校验器只做结构、引用、PNG 头尺寸与 alpha 格式检查；实际图片解码在浏览器进行，视觉质量需要人工检查。
6. 刷新游戏，在训练场显示判定框，测试轻重攻击、空击、三个技能和满气大招。
7. 测试 1V1、2V2 和两种挑战模式，确认头像和技能均能加载。

推荐将原始参考图与生成草稿放在项目的 `素材/<角色id>/`，它不进入静态构建。替换成图前自行保存旧版，不要运行占位图生成脚本覆盖新素材。

缺失动作、错误尺寸、重复 ID 或未知插件会显示具体字段并停用该角色，其他有效角色仍可玩。改完后重新检查和刷新即可恢复。
