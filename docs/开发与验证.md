# 开发与验证

## 模块职责

- `src/engine.js`：纯战斗状态、60Hz 更新、碰撞、AI、模式判定和挑战倍率。不依赖 DOM。
- `src/schema.js`：角色和招式公共类型说明、字段校验。
- `src/assets.js`：读取清单，校验并解码图片；无效角色隔离。
- `src/input.js`：双键盘映射、边沿输入、多指触控、失焦清理。
- `src/renderer.js`：Canvas 擂台、精灵和特效。与战斗判定独立。
- `src/app.js`：菜单、选人、回合、挑战、设置、存档和弹窗。
- `src/lab.js`：动作预览、本地 PNG 导入与浏览器导出。
- `src/plugins/`：显式注册的可信技能模块。
- `tools/`：仅使用 Node 内置模块的服务器、校验、静态构建和占位素材生成工具。

战斗内部坐标宽 1200、高 675，地面 y=510；角色物理 y 为离地高度，正值向上。绘制转换为 `地面 - 高度`。60Hz 时钟最多补算 0.25 秒，避免长时间挂起后突进；失焦则直接暂停。命中停顿期间冻结战斗时间。

## 命令与验证范围

`npm run check`：全部注册角色与模板的配置、唯一 ID、PNG 文件头／alpha 类型／尺寸、技能引用，以及所有源码、工具和测试的 JavaScript 语法。

`npm test`：使用 Node 内置测试框架，覆盖攻击阶段、一次命中、防御、资源与冷却、倒地起身、友军免伤、队伍判胜、超时、挑战倍率、训练恢复、护盾、增益、弹道、闪避、固定时钟、确定性 AI、模板扩展和改键冲突。没有外部测试依赖。

`npm run build`：先做完整检查，再清理固定的项目内 `dist` 目录并复制白名单文件。不会复制 tools、test、原图草稿或本机配置。构建没有压缩／打包步骤，便于直接检查产物。构建产物不调用后端 API。

`tools/placeholders.mjs` 是原创占位图生成器；默认发现已存在角色清单会拒绝覆盖。只有确实要重建全部占位素材时才用 `--force`，否则会覆盖三个内置角色与模板。无需在正常运行或构建时调用。

## 手动验收路径

1. 首页 → 单人 → 选人 → 对局 → 暂停 → 继续 → 结算 → 下一回合 → 比赛结束。
2. 同屏双人同时移动和出招，改键冲突应阻止保存，重载后设置仍在。
3. 2V2 验证四人同台、同队免伤、两名队员倒下才判负。
4. 训练切换三种木桩，关闭／打开恢复与能量，检查判定框和重置。
5. 两种挑战在首关选择强化、查看敌人；获胜继续，失败结束；验证最高纪录分开保存。
6. 实验室选择不同动作，暂停、逐帧、拖动时间条和翻转。导入透明 PNG，检查尺寸错误提示，导出 PNG 与 JSON。
7. 手机横屏验证移动加出招、多指抬起、触控取消；竖屏提示、旋转时暂停、浏览器切换后无残留按键。
8. 删除临时测试角色的图片，确认该角色停用、其他角色继续可玩，恢复图片后刷新正常。

## 边界

没有联机、账号、商城、云存档、录像、浏览器内代码编辑或自动 AI 生成。实验室导出不会覆写源文件。当前技能插件仅有文档中的受控能力，不承诺任意复杂机制可不改引擎直接实现。示例动作是可替换的程序占位图，不等同于精修角色动画。
